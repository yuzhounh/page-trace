# PageTrace 界面字号与密度调整

更新日期：2026-10-11。当前范围：完成长按菜单收窄；分析整体字号与界面比例。整体字号方案尚未实施。

## 当前结论

PageTrace 的“小一号”观感主要来自偏小的固定 CSS 字号和紧凑的导航尺寸。当前网页 viewport 为 `width=device-width, initial-scale=1.0`，未发现整页 CSS zoom 或整体 transform 缩小。Android `MainActivity.java` 明确设置 `setTextZoom(100)`，文字缩放不会按系统字体倍率调整。以上为源码及浏览器模拟结论，尚未在用户设备上比较物理显示尺寸、系统显示大小或实际安装版本。

手机/Android 当前尺寸（Chrome 模拟，加载当前源码样式及 Android 标记）：

- 页面基础字号：13px。
- 笔记标题：14.5px；普通正文：13.5px；引用/剪藏正文：13px。
- 日期导航文字：12px。Android 导航按钮固定为 36px 高，普通手机网页为 28px。
- Android 新建/编辑输入框：14px。`android-ui.css` 覆盖了手机网页原本的 16px 规则。
- 长按菜单：15px 文字，56px 行高。其操作项本来就比主界面更舒展。

LightNote 参考：`web/src/index.css` 的触屏编辑正文为 16px，常规触屏按钮至少 44px；`NoteContextMenu.jsx` 使用 280px 菜单和 56px 操作行。LightNote Android 列表标题/摘要也有 13.5px/12px 的紧凑设置，不能据此说 LightNote 所有区域都更大；更有用的参考是它的阅读、编辑与导航层级。

## 后续建议：按优先级独立实施

### 1. 先调整触屏阅读与编辑字号

- 页面基础字号建议 14px；普通正文与剪藏正文统一为 15px，行高 1.6。
- 笔记标题建议 16px，保持中等加粗；新建/编辑输入框统一为 16px。
- 日期、字数、辅助说明保持 12–13px，避免所有文字都同样醒目。
- 在共享触屏层使用明确的字号变量，并处理手机媒体查询与 Android 的覆盖关系。当前大量规则使用固定 px，仅修改根字号不会统一放大。
- 验证不同笔记类型、Markdown、编辑窗口及窄屏换行。这个步骤只调整阅读层级，不修改笔记数据。

### 2. 再协调导航与卡片留白

- 日期导航文字建议从 12px 调到 14px，按钮目标高度 40–44px。
- 顶部品牌建议 17–18px，顶栏约 48–56px；图标按职责保留 20–22px。
- 笔记卡片上下留白建议 14–16px、左右留白约 16px，不机械地把全部间距乘以固定倍率。
- 工具栏允许在最窄屏幕按功能分组换行，避免通过缩小文字或点击区域勉强维持一行。
- 长按菜单继续保持 280px 与 56px 操作行，不随主界面变大再次拉宽。

### 3. 检查 Android 系统字体适配并发布

- 布局适配完成后，再评估将固定 `setTextZoom(100)` 改为跟随系统字体倍率；需同时验证默认字体和较大字体、横屏与键盘弹出状态。
- 先以默认系统设置确定基线，再判断是否需要提供字号选项。第一轮无需新增整体缩放设置。
- 不建议使用全局 CSS zoom、transform scale、改变 initial-scale，或直接将 WebView 字体一律放到 110%：它们会连带改变菜单、弹窗、工具栏布局或字体与控件间的比例。
- 后续发布 Android 版本需要重新打包，因为 Gradle 会将网页/CSS 复制进 APK；网页发布不会自动更新已安装 APK 的内置页面。
